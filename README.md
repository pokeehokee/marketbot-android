# Marketbot

An Android app that runs automated trading strategies on **Kalshi** and **Polymarket US**,
entirely on the phone. Every method starts in paper mode (live public prices, no orders).
Live trading has to be armed per strategy through a checklist, a preflight and a typed confirmation.

## Strategies

| Strategy | Venue | Evidence | Ported from |
| --- | --- | --- | --- |

| BTC deep-ITM ladder: join near-certain bids in the last 50 min | Kalshi KXBTCD | Reported +$129 on ~1,260 settlements. Not verifiable: the original code was lost | `weatherbot` branch `ccr-f6dc9b99-xbiukn` |
| BTC deep-ITM on Polymarket's daily 5 PM ET ladder | Polymarket US | **Unproven.** The rule was never measured on this ladder | new adapter for the same rule |
| Liquidity-reward farming | Polymarket US | **Unproven.** Estimated ~$108/day; $0.26 actually paid | `polymarket` (pmfarm) |

Adding a method means implementing `Strategy` (`core/.../strategy/Strategy.kt`) and listing it in
`StrategyRegistry`. Its settings form, go-live checklist, preflight and stats screens are generated from the class.

## Where every number comes from

Each value carries a `Sourced` tag, shown as a chip in the app:

- **KALSHI / POLYMARKET / VENUE**: read verbatim from that API's field. The field is named, e.g. `GET /portfolio/balance#balance_dollars`.
- **CALC**: the API has no field for it, so the formula is shown along with the reason, e.g. `1 - no_bid` when a market has no `yes_ask`.
- **PAPER**: produced by the simulator. Never mixed with live figures.
- **SETTING**: a value you set.

Tap any number to see its exact origin. **Settings > Data sources** lists the latest reading of everything.
The rule is API first. Kalshi live P&L comes only from `/portfolio/settlements`, and a settled row waits rather than being
graded from local size and price. A missing value pauses or skips; it is never read as zero.

## Testing

- `core` (pure Kotlin, 64 tests). The strategy maths, selectors, fee, fill models, BTC volatility and reward scoring are
  compared against the **original Python** run on thousands of inputs (`core/src/test/resources/golden`, generated by
  `golden.py` from the weatherbot and polymarket sources). Signing is checked byte for byte against the official
  Polymarket SDK and verified against Kalshi's RSA-PSS scheme. Clients and strategies run end to end against a scripted
  fake exchange: no orders in paper, shard routing, post-only, no POST retry, deferred grading, the brake, the fee-type
  kill and the kill switch.
- `app` (Robolectric). Room stores round-trip every source, the vault never stores plaintext, and the screens render
  (screenshots in the CI artifact).

```bash
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug
```

## Install

CI builds a debug-signed APK on every push. Pushes to the default branch publish it as a GitHub pre-release; open the
APK on the phone to install it (allow "install unknown apps" for your browser). The debug key is checked in
(`signing/debug.keystore`) so each build installs over the last. For a private release key, set the
`RELEASE_KEYSTORE_*` environment variables in CI.

## Running on a phone: limits to know

- Android can suspend background apps. The engine runs as a foreground service with a wake lock. Exempt the app from battery
  optimisation (the Home banner does this) and from your phone maker's own battery manager.
- BTC deep-ITM re-quotes every 2-5 s near the close. Keep the phone charging and online during that window.
- Run **one bot per account**. Before arming, the longshot checks that the account has no resting orders or positions
  the app doesn't know about. Turn off any desktop or VM runner first.
- Kalshi's crypto markets live on exchange shard 2, which needs its own cash. Deep-ITM orders and cancels are routed there.
